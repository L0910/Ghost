# 项目架构说明

> 记录日期：2026-09-07
> 记录人：L0910

## 1. 总体架构

系统采用"核心不变，主题扩展"的架构策略：

- **Ghost核心**：负责认证、内容、标签、会员、评论等基础能力，不做修改
- **自定义主题**：负责页面展示、交互逻辑和自主扩展功能，是二次开发的主要边界
- **Content API**：主题通过Ghost内置助手和Content API访问内容数据
- **SQLite数据库**：持久化存储所有业务数据

## 2. 请求处理流程

1. 用户请求到达Ghost服务器（默认端口2368）
2. Ghost核心路由判断请求类型（前台页面/管理端/API）
3. 前台页面请求进入主题引擎，加载对应Handlebars模板
4. 模板通过Ghost Helper获取数据
5. 数据服务层通过Knex.js查询SQLite数据库
6. 渲染完成的HTML返回给用户浏览器
7. 浏览器加载主题的CSS/JS资源，执行前端交互

## 4. 本人修改边界

### 允许修改的目录
- `theme/oss-blog-theme/` — 自定义主题全部文件
- `docs/` — 实验相关文档
- `tests/` — 测试用例和记录
- 根目录的 `README.md`、`NOTICE.md`、`.gitignore`

### 禁止修改的目录
- `ghost/core/core/` — Ghost核心代码
- `apps/` — 前端应用
- `packages/` — 内部包
- `ghost/core/content/` — 运行时数据（不提交Git）

### 修改边界的理由
1. 升级友好：不修改核心代码，后续Ghost升级时不会冲突
2. 职责清晰：主题负责展示，核心负责业务
3. 可维护性：自定义代码集中在theme/目录
4. 开源规范：符合Ghost官方推荐的扩展方式

## 5. 自主扩展功能架构

### 相关文章推荐
- 位置：文章详情页底部
- 数据来源：Ghost内置{{#get}}助手，通过Content API查询同标签文章
- 实现：Handlebars partial + 标签匹配 + 排除当前文章
- 隐私影响：纯服务端渲染，不收集用户数据
- 失败状态：文章无标签或无相关文章时不显示

### 搜索高亮与导航
- 位置：全站（URL带搜索参数时触发）
- 数据来源：URL参数 ?s=、?search=、?q=
- 实现：纯前端JavaScript，遍历文本节点，mark标签高亮
- 功能：高亮匹配、上一个/下一个导航、键盘快捷键、关闭高亮
- 隐私影响：纯浏览器端处理，不发送数据到服务器
- 失败状态：关键词为空或无匹配时显示友好提示

## 6. 技术栈总结

| 层级 | 技术 | 说明 |

| 运行时 | Node.js 22 LTS | Ghost运行环境 |
| 核心框架 | Ghost 5.x | 内容与会员平台 |
| 数据库 | SQLite 3 | 本地开发数据库 |
| 主题模板 | Handlebars | Ghost主题模板引擎 |

| 前端脚本 | 原生JavaScript | 无框架依赖 |
| 包管理 | pnpm | monorepo包管理 |
| 版本控制 | Git | 代码版本管理 |
